# 废物进化论 · 物的觉醒

四件物品，慢慢成为自己。以真实 Aholo Lux3D 生成模型为主体，补充形态变化和动作动画的3D进化展。

## 四条进化路线

| 展品 | 五个阶段 | 动作 |
| --- | --- | --- |
| 水杯 | 原物、苏醒、行走、感知、绽放 | 三足交替落地、触角探查、冠瓣开合 |
| 椅子 | 原物、苏醒、迈步、探身、舒展 | 原有椅腿迈步、椅背转向、软垫呼吸与伸展 |
| 雨伞 | 原物、苏醒、浮游、感风、舒展 | 伞面呼吸、浮游、伞沿波动与伞柄平衡 |
| 垃圾桶 | 原物、苏醒、挪动、感知、开合 | 左右承重挪动、桶壁收放、真实桶盖铰链开合 |

页面顶部切换物品，每件分别保存进度。每次进化结束自动演示动作，支持暂停、重播、回看阶段、从头开始。切换物品会取消前一件尚未结束的播放。

背景随进化缓慢变换雾色，细颗粒展台、倒角、金属嵌线与阴影均在本地生成。没有挑战、卡牌、血量或胜负。

## 模型来源

当前四件主体都加载真实Lux3D生成的GLB，保留原有纹理和材质。杯子已从早期程序化样例换成真实Lux3D杯身，继续沿用样例的关节足、触角、冠瓣与动作效果。

**原始GLB没有骨架和动画。** 模型分区形变、关节、附加生长结构和演示动作由本作品后制，不能把后制动画称为生成模型自带能力。页脚可查看说明并下载未经动画加工的原始GLB。

## 启动

Node.js ≥20：

```bash
npm install
cp .env.example .env      # 填入 AHOLO_API_KEY；仅服务端使用
npm run build
npm start
```

打开 http://localhost:8787/ 。开发使用 `npm run dev`，前端 http://localhost:5173/ 。也可直接打开 `?object=cup`、`?object=chair`、`?object=umbrella`、`?object=bin`。

## 自主进化工作台

打开 `?create=1`，或点击展台顶部“自主进化 ＋”。这是独立于四件预制展品的创作区：

1. 输入作品名称和第一代物品描述，提交到服务端 Aholo Lux3D 接口。
2. 生成完成后旋转观察、下载原始GLB；可以选择明确标记为后制的轻呼吸/悬浮展示动作。
3. 自己输入下一次变异，或点击灵感建议填入后修改。提交前可查看完整提示词。
4. 点击任意已完成的一代，从那里生成另一条分支。每代提示词、父节点、任务编号和模型地址分别保存。
5. 刷新后恢复已有任务；停止本页等待不会取消Aholo任务，可稍后继续查询。失败后可修改描述重试；相同提示词复用已有任务/模型，避免无意重复提交。
6. 记录保存在当前浏览器，可导出JSON。新建作品会替换当前工作台记录，界面会提醒先导出；预制展品进度不受影响。

连接使用服务端 `.env` 中的 `AHOLO_API_KEY` 与 `AHOLO_API_BASE`，浏览器不会接收密钥。生成会使用账号额度。任务信息保存在模型目录下的隐藏文件 `.jobs.json`（Express静态文件服务默认不暴露点文件），服务重启后可恢复。

每一代是根据原始描述、祖先变异和新指令重新生成，不是对上一代网格做精确编辑，外形继承可能存在差异。长谱系优先保留原始物品与最近的变异。生成模型不自带关节动画，工作台的展示动作与四件手工后制展品明确分开。

检查：`npm run test:workshop`、`npm run test:workshop-ui`。浏览器测试使用模拟任务响应和真实本地GLB，覆盖异步等待、刷新续等、失败/编辑/重试、分支继承、停止/恢复、预览动作、暂停、导出与手机布局。真实Aholo连接通过查询已有完成任务验证；另验证线上本地服务的缓存提交与输入校验，没有为测试额外创建付费模型。
