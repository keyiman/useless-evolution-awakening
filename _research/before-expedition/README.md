# 废物进化论：不适者生存

**Useless Evolution: Survival of the Least Useful**

2026 Aholo 全球 3D AI 黑客松参赛作品 · 交互式 3D 人工进化游戏

> 选一个日常物品，输入一个种子，看它在六种结构算子下逐代“升级”，
> 直到它仍然装满了水，却拒绝让任何人喝到。

---

## 1. 作品是什么（当前默认：器官库）

一个由 **Aholo Lux3D 预生成资产**驱动的“器官组合”实验。所有可见几何都在赛前用 Lux3D 建好，
运行时不调用任何模型接口；玩家只做组合、融合与观察。

- **4 个基础物体**：水杯 / 椅子 / 雨伞 / 垃圾桶（Lux3D 生成的整件 GLB）
- **32 个器官**：密封盖、倒置伞面、太阳能板、天线、气球、降落伞、滤芯、灯罩、机械臂、巨柄、寄生装置、扬声器、摄像头、储液罐、仪表、锁扣、铰链、齿轮、管道、阀门、喷气口、藤壶、轮式底盘、吸盘、钻头、机械腿、弹簧、菌丝、稳定环、防护笼、散热鳍、羽毛（全部 Lux3D 生成）
- 每个基础物体最多叠加 4 个器官，共 **4.1 万种组合 × 4 个基础物体**
- **跨物种融合**：把第二个基础物体嵌进当前个体，形成“杯子长在椅子上”的嵌合体
- **自主变异**：不点任何按钮，物体会每 4.8 秒自己长出 / 掉落一个器官
- 评价不是黑箱：右侧直接显示 `U = 基础值 − 器官代价` 的算式，每个器官的功能影响都能在模型上看到
- 无用性测试直接对**当前拼装出的 GLB** 做倾斜 / 移动 / 震动，结论与器官结构一致

旧版“三选一进化树”保留为**拓展模式**：访问 `?tree=1`，或在器官库左下角点“拓展模式”。

### 1.1 拓展模式：三选一进化树

玩家选择水杯 / 椅子 / 雨伞 / 垃圾桶，输入世界种子；每一代系统给出三个候选分支，
每个分支都由一条**可复现的规则**产生，并伴随可见的几何变化。选中的分支会交给
**Aholo Lux3D（G1-Turbo 文生 3D）** 生成 GLB，在浏览器里可旋转、缩放、对比；
随后进入“无用性测试”，用规则驱动的动画演示它如何一步步失去原本的用途。

- 六种核心算子：增生 M1 / 变比 M2 / 反转 M3 / 递归 M4 / 融合 M5 / 寄生 M6
- 八种稀有事件：返祖、基因污染、器官独立、功能夺舍、共生冲突、奇迹进化、环境错配、递归增殖
- 四类祖先、每代三候选、五代以上分叉、DAG 谱系、双亲杂交
- 同种子同路径 100% 复现（离线 400 条路径校验，0 次不一致）
- Lux3D 真实调用：任务创建 → 轮询 → GLB 下载 → 本地缓存 → 浏览器加载

## 2. 快速开始

要求 Node.js ≥ 20。

```bash
npm install
cp .env.example .env      # 填入 AHOLO_API_KEY
npm run dev               # Vite :5173 + API :8787
```

打开 http://localhost:5173 。

生产模式：

```bash
npm run build
npm start                 # 单端口 8787 同时提供前端与 API
```

Docker：

```bash
docker build -t useless-evolution .
docker run -p 8787:8787 -e AHOLO_API_KEY=xxx useless-evolution
```

> 密钥只存在于服务端环境变量。前端任何代码、构建产物、分享链接中都不包含密钥。

## 4. 可复现的随机

设世界种子 `s`、父节点内容哈希 `h`、候选槽位 `k`、规则版本 `v`：

```
key = `${v}|${s}|${h}|${k}`
rng = mulberry32(cyrb128(key)[0])
```

- `h` 由稳定序列化后的基因型 + 父哈希 + 算子键计算，不使用前端自增序号；
- 三个候选各自独立，先探索别的分支不会改变原节点候选；
- 规则版本 `ue-1.1.0` 写入分享链接，版本不符时拒绝重放而不是给出错误结果；
- 模型是否生成成功不影响谱系：失败只落在表现型，基因与路径仍在。

离线校验（`npm run test:engine`）：100 个种子 × 4 家族 × 5 代 × 两次重放，
确定性不一致 0 次、非法数值 0 次、候选算子重复 0 组。

## 5. 评分与“无用”

每个节点记录四维：

| 维度 | 含义 |
| --- | --- |
| U 实用性 | 四/五项功能指标的加权几何平均与算术平均混合，任一项归零都会显著拉低 |
| N 新颖度 | 算子种类、代际、异物部件、稀有事件、结构反转 |
| A 荒诞度 | 部件数、冲突数、嵌套深度、维护成本、自主移动 |
| R 辨识度 | 仍保留的祖先身份标记比例 |

综合 `Q = 0.30N + 0.30A + 0.20R + 0.20D`，其中 `D` 衡量本代与父代的功能落差。
评分只用于排序与展示，不声称是物理真实性度量。

“无用”必须可解释：每次失败都会指向一个具体结构冲突（密封盖 vs 饮用口、护栏 vs 坐面、
倒置伞面 vs 遮挡面……），并由 `uselessTest.ts` 转成可重放的测试步骤。

## 6. Lux3D 接入

服务端 `server/lux3d.ts`：

1. `POST /lux3d/v1/generate/text-to-3d/task/create`
   `{ prompt, version: "G1-Turbo", outputFormat: ["glb"], faceCount: 120000, enablePbr: true }`
2. 每 4 秒 `GET /lux3d/v1/generate/task/get?taskid=...`
   状态：`0` 初始化 / `1` 进行中 / `3` 成功 / `4` 失败 / `6` 取消
3. 成功后立即下载 `outputs[].content` 到 `public/models/<promptHash>.glb`，
   记录 taskId、大小、时间、提示词到 `manifest.json`（官方结果 URL 仅 2 小时有效）
4. 前端通过 `/api/assets/lookup` 命中缓存则秒开；未命中才创建新任务

接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/lux3d/generate` | 创建任务（同提示词命中缓存则直接返回） |
| GET | `/api/lux3d/task/:taskId` | 查询并落盘 |
| POST | `/api/assets/lookup` | 按提示词查本地缓存 |
| GET | `/api/lux3d/stats` | 资产数量、体积、任务记录 |

失败处理：前端保留程序化草模、显示错误原因、允许重试；不删除节点、不阻塞下一次操作。
并发限制：同一时间只允许一个生成任务，避免 `GENERATION_CONCURRENCY_LIMIT_EXCEEDED`。

## 7. 预生成示范资产

```bash
npx tsx scripts/generate-assets.ts cup          # 水杯 G0–G5
npx tsx scripts/generate-assets.ts chair umbrella bin
npx tsx scripts/generate-assets.ts all
```

脚本使用与网页完全相同的引擎和提示词，因此生成结果的缓存键与玩家点到同一节点时一致。
所有资产都是真实 Lux3D 任务产物，`manifest.json` 保留 taskId 与时间，可直接作为参赛证据。

## 8. 三层几何策略

1. **程序化草模**：任何候选立即可见，不消耗积分；由参数化零件与挂接锚点组成。
2. **Lux3D 完整生成**：选中分支后异步生成 GLB，成功则替换草模。
3. **动作与测试**：测试模式固定使用程序化草模，保证关节/位移/雨雪等动画可控，
   不假设 AI 网格自带可动骨架。

## 9. 3D 表现与镜头

- **环境光**：用 three 的 `RoomEnvironment` 在本地烘焙 PMREM 环境贴图，金属与釉面有真实反射，
  不依赖外网 HDR，离线也能出图。
- **灯光**：主光（带 2048 阴影）+ 冷补光 + 暖轮廓光 + 正面柔光，ACES Filmic tone mapping。
- **接地**：渐变地面 + 雾 + ContactShadows + 平行光投影，模型不再“悬浮”。
- **模型归一化**：GLB 自动居中、按包围盒缩放、底部贴合展台；入场有 0.4 秒的轻微生长过渡。
- **转台**：观察模式缓慢自动旋转，拖拽可接管；截图/对比用 `?spin=0` 关闭。
- **测试动画**：雨丝（线段雨而非点）、密封杯观察窗与水珠、人偶行走/前倾、纸张抛掷。
- **降级**：GLB 加载失败或尚未生成时自动使用程序化草模，不阻塞交互。

## 10. 已知限制

- Lux3D 单次生成约 2–6 分钟，首次体验需要等待；示范链已预生成。
- 跨代拓扑不保证连续，因此采用“结构描述继承 + 重新生成 + 程序化部件”并行策略，
  不声称支持局部网格变形。
- 无用性测试是规则驱动的游戏演示，不是机械工程仿真。
- 分享链接只复现规则与谱系，不保证对方浏览器中的 AI 网格逐顶点一致。
